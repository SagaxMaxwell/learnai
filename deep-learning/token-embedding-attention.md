# Token、Embedding 与 Attention

## 总比喻：文字进入一座翻译工厂

文字不能直接进入神经网络。它要先换成工厂能处理的编号，再换成带有丰富信息的数字卡片，最后在流水线上互相参考。

## 1. Token：文字的积木

Token 不一定等于单词，可能是：

- 一个汉字
- 多个汉字
- 一个英文单词
- 英文单词的一部分
- 标点或特殊符号

比喻：Tokenizer 像切积木的机器。不同模型的刀法和积木盒不同，所以同一句话可能切出不同 Token。

## 2. Token ID：积木编号

```text
今天 → 1832
天气 → 9271
很好 → 441
```

这些数字只是仓库编号，不是语义分数。编号本身不表示“天气比今天更大”。

## 3. Embedding：给每块积木做多维档案

模型内部有一个表：

```text
Token ID → 高维向量
```

比喻：编号只像仓库货架号，Embedding 才像这块积木的详细档案。档案有很多隐藏刻度，整体描述它在语言中的使用方式。

Embedding 是训练出来的，不是人手写的词典定义。

## 4. 位置：给积木贴顺序标签

```text
我 爱 你
你 爱 我
```

如果没有位置信息，两组积木只是同一批材料。因此模型还要加入位置表示，知道谁在前、谁在后。

## 5. Attention：积木之间互相传纸条

处理一个 Token 时，模型需要判断应该参考哪些其他 Token、参考多少。

比喻：每块积木都可以向其他积木发出“请提供相关信息”的请求，再按相关程度收回信息。这样“它”可以根据上下文判断更可能指书还是桌子。

## 6. Query、Key、Value

- Query：我正在寻找什么信息？
- Key：我提供什么线索，可以怎样被匹配？
- Value：匹配后真正取走的内容

比喻：Query 像顾客的问题，Key 像商品标签，Value 像商品本身。Attention 先用问题和标签匹配，再取回商品内容。

## 7. 上下文窗口

模型一次能处理的 Token 数量有限，这个上限叫上下文窗口。

比喻：工厂的工作台大小有限。资料越多，不代表工人一定能同样清楚地使用每一页，因此还要做好筛选、排序和组织。

## 8. 常见误解

- Token 不一定是单词
- 向量维度不等于词语数量
- 模型不是先生成一个固定的“句子向量”再思考全部内容
- Attention 是数学上的信息加权机制，不等于人类意识
