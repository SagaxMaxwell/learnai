# Transformer 与大语言模型

## 总比喻：一座层层加工的语言工厂

Token 是原材料，Embedding 是带信息的材料卡，Attention 是材料之间互相查阅，Transformer 是重复多次的加工车间，最终输出下一个 Token。

## Transformer 的主要组件

- Token Embedding
- 位置信息
- Self-Attention
- 前馈神经网络
- 残差连接
- Layer Normalization

这些组件通常会堆叠很多层。

## 预训练：看海量练习题

模型反复完成“预测下一个 Token”的任务：

```text
输入：今天的天气很
目标：好
```

比喻：给学徒看海量书籍，每次遮住下一块积木，让它猜答案。猜错后，工厂里的参数齿轮被微调。

## 指令微调：学习听懂任务

预训练模型熟悉语言模式，但不一定会按照用户要求回答。指令微调用问答、任务和偏好数据，让学徒学会“按要求工作”。

## 生成：一次只生产一块积木

```text
读取已有上下文
→ 计算下一个 Token 的概率
→ 根据解码策略选择一个 Token
→ 把它放回工作台
→ 继续
```

比喻：工厂不是一次写完整篇文章，而是每次生产下一块积木，再根据已经生产的内容继续决定下一块。

## 解码参数

- Temperature：让选择更保守或更随机
- Top-k：只在概率最高的若干候选中选择
- Top-p：选择累计概率达到阈值的一组候选

比喻：这是控制工人是否只选最稳妥材料，还是允许尝试更多替代材料的规则。

## 为什么模型会出错

- 训练资料本身有错误或偏见
- 工作台上缺少必要上下文
- 模型生成了语言上合理但事实不真的内容
- 任务超出已学模式或推理能力
- 外部工具返回了错误结果

所以可靠的 LLM 应用需要检索、工具、评估、权限和人工确认等外部机制。

## 需要区分

- 预训练：学习一般语言和世界模式
- 微调：适应特定任务或风格
- Prompt：运行时给出的工作说明
- RAG：运行时送进来的外部资料
- 工具调用：运行时请求外部程序执行动作
