# MCP、RAG、Agent 与 Skill

## 总比喻：一座工厂的标准接口、工长和操作手册

- MCP 是统一的插接口和通行标准
- Tool 是插上去的机械臂或可调用函数
- Resource 是可以读取的资料柜内容
- RAG 是“先检索资料，再生成回答”的工作流程
- Agent 是会安排工作的工长
- Skill 是某类工作的操作手册

## MCP 是什么

MCP（Model Context Protocol）是一种连接 AI 应用与外部工具、数据和提示模板的协议。

常见概念：

- MCP Host：承载 AI 应用的程序
- MCP Client：应用中负责连接服务器的一侧
- MCP Server：提供工具、资源或提示的一侧
- Tool：可以被调用的动作
- Resource：可以读取的上下文数据
- Prompt：可复用的提示模板

MCP 解决的是“如何统一连接”，不是“如何自动保证安全”，也不是一个外部知识库。它不会自动解决权限、参数、结果可信度或模型决策错误。

MCP Server 可以提供三类能力：

- **Tools**：搜索、查询、读写文件、调用 API 等可执行动作
- **Resources**：文件、数据库记录、项目资料等可读取内容
- **Prompts**：可复用的提示模板

因此，知识库可以通过 MCP Resource 暴露，也可以通过 MCP Tool 提供搜索接口；但 MCP 本身不是知识库。

## Agent 的最小循环

```text
接收目标 → 读取状态 → 选择下一步 → 调用工具 → 检查结果 → 继续或停止
```

比喻：工长接到任务后，先看库存和进度，再决定叫哪台机器；如果结果不对，就返工或换方案。

可靠的 Agent 必须有明确边界、工具列表、状态管理、最大步数、超时、错误恢复、高风险操作确认和日志。

## Skill 是什么

Skill 是针对一类任务的可复用工作说明，通常包括任务目标、适用场景、步骤、工具规则、输出要求、示例和失败处理。

比喻：Skill 像“如何制作一份报表”的岗位手册；它不是模型，也不是单个 Tool 或 MCP Server。

在某些平台中，Skill 目录可以附带脚本、参考文件甚至工具调用说明。因此从“一个完整 Skill 包”来看，它可能包含可执行内容；但概念上仍要区分：

```text
Skill：告诉系统一类工作应该怎么做
Tool：执行一个具体动作
```

## RAG 是什么

RAG（检索增强生成）是一个应用流程：

```text
用户问题
→ 形成检索 Query
→ 查询知识库
→ 得到相关文档片段
→ 将片段放入模型 Context
→ 模型生成回答
```

RAG 不规定必须使用 MCP。检索可以由普通代码、向量数据库 API 或 MCP Tool 完成。

如果使用 MCP，关系是：

```text
RAG 流程
→ 调用 MCP Tool 或读取 MCP Resource
→ 获得知识库内容
→ 放入 Context
→ LLM 回答
```

## 几个概念的关系

```text
Skill：告诉系统怎么做
Agent：决定下一步做什么
Tool：执行具体动作
MCP：规定工具和数据如何连接
```

一个系统可以只使用其中一部分：Prompt、RAG、工具调用、固定 Workflow，或者它们的组合。

| 概念 | 作用 | 本身是什么 |
|---|---|---|
| Skill | 提供一类工作的做法 | 工作说明和相关资源 |
| Tool | 执行一个具体动作 | 可调用函数或操作 |
| MCP | 统一连接外部能力 | 协议 |
| Resource | 提供可读取内容 | 数据或上下文入口 |
| RAG | 找资料后辅助回答 | 应用流程 |
| Agent | 动态决定并执行步骤 | 运行系统 |

## 安全底线

- 工具使用最小权限
- 对文件、网络和数据库操作设置范围
- 外部文本不能自动覆盖系统规则
- 高风险动作需要人工确认
- 记录输入、工具请求、工具结果和最终动作
- 测试提示注入、数据泄露和越权

## 推荐实践顺序

```text
单次 Prompt → 结构化输出 → RAG → 单个工具 → 固定 Workflow → Agent → MCP 多工具 → Skill 化和评估
```

不要一开始就做多 Agent。先证明单个步骤可靠，再增加自主性。
