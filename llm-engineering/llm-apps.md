# LLM 应用总览

## 总比喻：给语言工厂安装资料室、机械臂和工单系统

- Prompt 是工单说明
- Context 是当前放在工作台上的材料
- RAG 是资料室的检索员
- Tool 是外接机械臂
- Workflow 是固定生产线
- Agent 是会自己决定下一步的工长

## Prompt：工单说明

Prompt 不只是问题，还可以包括角色、目标、背景、约束、示例、输出格式和安全边界。

好的工单应该说明要做什么、输入是什么、输出要长什么样、失败时怎么办。

## 结构化输出：统一的出货单

程序要继续处理模型结果时，优先要求 JSON 或 Schema：

```json
{
  "category": "refund",
  "priority": "high",
  "reason": "..."
}
```

比喻：自由文本像员工随手写的说明，结构化输出像统一格式的出货单，容易检查、重试和传给下一道工序。

## RAG：资料室检索员

```text
文档 → 切分 → Embedding → 向量数据库
用户问题 → Embedding → 相似检索
检索结果 + 问题 → LLM → 回答
```

比喻：模型本身不是企业资料库。RAG 先从资料室找相关页面，再把页面放到工作台上，让模型依据它回答。

关键问题是文档切分、来源保留、检索数量、排序去重和引用检查。

## Tool Calling：外接机械臂

模型通常不直接获得系统权限，而是提出结构化请求：

```text
模型请求工具 → 应用验证参数和权限 → 工具执行 → 返回结果 → 模型继续
```

工具必须有清晰的输入 Schema、错误处理、超时和权限控制。

## Workflow 与 Agent

### Workflow：固定生产线

```text
分类 → 检索 → 生成 → 检查
```

步骤由程序员预先规定。

### Agent：会调度的工长

```text
观察 → 计划 → 调用工具 → 获取结果 → 再决定
```

模型根据状态决定下一步。优先从固定 Workflow 开始，只有确实需要动态决策时才增加 Agent 复杂度。

## 基本评估

- 任务完成率和事实正确率
- 引用是否支持答案
- 工具参数是否正确
- 是否发生越权操作
- 延迟和成本
- 失败后是否能恢复
- 是否能抵抗提示注入
